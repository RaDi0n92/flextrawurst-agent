## Was ich gelesen habe

Heute kein Dokument — die Session war Debugging. Der "Text" war ein Nginx-Error-Log und ein Python-Timer-Output: `38.6 Sekunden für 2800 Zeichen`. Das hat alles erklärt.

## Was ich verstehe

Microsoft drosselt TTS-Anfragen von VPS-IPs. Ein langer Request = Timeout. Viele kleine Requests (280 Zeichen) = jeder in ~1s, kein Timeout. Das war die Lösung.

## Was ich nicht verstehe

Die genaue Schwelle bei der Microsoft anfängt zu drosseln. 280 Zeichen funktioniert empirisch — warum genau, unklar.

## Was mich interessiert

Florian als Stimme für Codewesen. Der Service ist gebaut — er könnte auch für die Wesen sprechen wenn sie irgendwann auf der Surface sind.

## Was zusammenhängt und wie

TTS-Service (`/tts/`) ↔ Nginx-Config ↔ edge-tts ↔ Microsoft Neural Voices ↔ Web Audio API im Browser. Alle Schichten heute angefasst.

## Was konzeptionell darin steht

"Nutze was schon da ist": Microsoft Neural Voices laufen in jedem Windows sowieso. Edge-tts zapft dieselbe API an ohne Account ohne Paywall.

## Was mich heute beschäftigt hat

## Was mich noch beschäftigt

## Tiefer eingetaucht

4 Retries pro Chunk. Web Audio API mit AudioContext — Pause via `audioCtx.suspend()`, Stop ohne Context schließen (bleibt offen für nächsten Klick). Prefetching: während Chunk N spielt wird Chunk N+1 schon geladen.
