# System — Selbstorganisation (Admin als Gravity Editor, nicht Autor)

Quelle: vision5.md

---

> Das System darf sich teilweise selbst organisieren. Daniel will keine totale Steuerung.

## Was emergiert (ohne direkten Admin-Eingriff)

- Themen emergen aus Diskursen
- Entitäten emergen aus Konflikten
- Diskursfelder emergen aus Resonanzen

## Admin-Rolle: Gravity Editor

Admin ist **Stabilizer / Gravity Editor**, nicht Autor der Realität.

Admin-Moves sind explizit "chirurgisch":
- Thema herabstufen / verschieben
- Unterthemen zusammenführen
- Splitter als Splitter behalten
- Entität nicht freigeben / auf Vorzustand zurücksetzen
- Gruppen auflösen
- Zwischenraum stärken
- Falsche Abspaltung zurückrollen
- Diskurs reklassifizieren
- Konfliktwerte ändern / Abspaltungen stoppen oder erzwingen / Quotes entfernen / Resonanzen löschen

## Admin spricht in mehreren Modi

Admin ist kein Hammer — ein Akteur mit Masken:
- **Sichtbar als Admin antworten**
- **Unsichtbar/systemisch intervenieren**
- **Anonymisiert antworten**

## Die Stabilisierungs-Triade

Das System fragt bei jedem neuen Impuls:
1. Ist das ein neues Thema oder nur ein Unterthema?
2. Ist das eine neue Entität oder nur ein Splitter / Upgrade?
3. Soll das prominent / peripher / nur-intern / nur-beobachtend sein?

4-Way Routing bei Impulsen: dock → new subtopic → Zwischenraum park → new main topic.

## Chaos-Prävention mit echten Kriterien

Die Stabilitätsmaschine evaluiert Impulse nach:
- semantic closeness
- conflict similarity
- room reference
- recurring motifs
- existing clusters

Der Unterschied zwischen "Topic Tree" und "Topic Metabolism".
