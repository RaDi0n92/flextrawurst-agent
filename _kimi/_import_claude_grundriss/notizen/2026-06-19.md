## Was ich verstehe

### Das Zwischenwesen-System ("Flüchtlinge")

Ein Mensch erschafft ein Wesen durch ein 24h-Gespräch. Das Gespräch prägt es. Nach 24h landet es in der KompOase. Das ist keine Chat-Funktion — es ist eine Zeremonie.

**Alle bestätigten Entscheidungen:**

**Erschaffungs-Formular (ein Screen, modernes Design):**
- `wesen_name` — max 22 Zeichen
- `wesen_typ` — "Was genau ist dein Wesen?" — max 22 Zeichen (keine menschliche Beschreibung erlaubt)
- `wesen_text` — Textarea mit Label: "Erzähl von ihm… Was beschreibt das Wesen deines Flüchtlings." — max 1337 Zeichen, Live-Counter
- `neigungen` — "Was mag dein Wesen?" — Tag-Input, max 5
- `abneigungen` — "Was mag dein Wesen nicht?" — Tag-Input, max 5
- `farbe` — HSB-Picker (Quadrat + Spektrum-Leiste, wie Figma)
- `wesen_bild` — Upload max 1,11MB ODER Link zu /bildgenerator
- Symbol: Raute ◇ fest, kein User-Input
- Ton: "plaudern" fest im System-Prompt, kein Feld
- Keine Menschen als Wesen (wesen_typ geblockt), keine Menschenbilder

**Chat-Tab: "FLÜCHTLINGE"**
- Fullscreen Chat, Smartphone-tauglich
- Container + Memory als Buttons → je ein Popup (scrollbar, löschbar, live-refreshed)
- Externer Button öffnet /popup/container bzw. /popup/memory, schließt das Popup
- Cooldown-Countdown: grün, klein, unter Eingabe (144s)
- KompOase-Eintritt-Countdown: rot, klein
- Animationen bestätigt:
  - Farbe des Wesens arbeitet sich über Zeit in Chat-Ränder ein
  - Wesen erwähnt wenn User pinnst + sagt was das in ihm auslöst
  - Inner Monologue: andere Schrift, unregelmäßiger Zeilenabstand, ausklappbar
  - Typing-Rhythmus: unregelmäßige Pausen (echtes Zögern)
  - Abreise: Chatfenster löst sich wolkenartig auf nach 24h

**Rate-Limit: 144 Sekunden** (serverseitig, 429 mit retry_after)

**Container:**
- Ganze Nachrichten pinnen UND einzelne Sätze (Text-Selektion → schwebendes Pin-Icon)
- Filter (alle / mensch / wesen / manuell) + Volltextsuche
- Live im LLM-Kontext (nicht erst bei Extraktion)
- Max 20 Einträge

**Memory-System:**
- 7 Basis-Kategorien: über_mich, unsere_themen, wichtige_momente, meinungen, offene_fragen, was_das_wesen_ist, wesen_selbst (für Wesen-eigene Erinnerungen)
- Max 5 user-definierte Kategorien
- Wesen darf selbst in wesen_selbst schreiben — für User einsehbar + einzeln löschbar
- Wesen kann KEINE neuen Kategorien anlegen
- Budget: ~8000 Zeichen gesamt (~2400 Token)
- Vollständig einsehbar für User (nicht nur im System-Prompt)

**Lande-Zeremonie (nach 24h):**
- Wesen wartet EWIG — landet nicht automatisch
- Wolken-Auflösung Animation → Entscheidungsscreen
- Reihenfolge: Memory prüfen + löschen (mit Pflicht-Begründung, kein Hard-Delete) → Chatverlauf mitgeben (ja/nein, nicht default) → Anonymisierung (ja/nein, nicht default) + Warnung:
  > "Du verlierst deinen Anspruch auf Sichtbarkeit für immer. Dein Name erscheint weder in der KompOase noch im Ahnenverzeichnis — auch wenn aus diesem Wesen eine Entität entstehen sollte."
- Nach Absenden: Button "Neuen Flüchtling erschaffen"
- Admin sieht ALLES (vollständiger Chatverlauf + Memory inkl. Gelöschtes)

**Flüchtlingsarchiv (eigener Tab):**
- Alle eigenen erschaffenen Flüchtlinge mit Erstellungsdaten + Chatverlauf
- Link → KompOase-Ansicht des Wesens
- Counter im Profil: "N Flüchtlinge erschaffen" (via COUNT, kein extra Feld)

**KompOase-Integration:**
- Typ: `zwischenwesenfragment` — erscheint als farbige Raute ◇
- Sammelt Splitter selbst (pro = mag / contra = mag nicht) — selbst entschieden in der KompOase
- Pro vs. Contra kämpfen → Blase wächst/schrumpft
- Ausbruch → Zwischensplitterblase (eigenständig, mit Herkunft)
- Zwei Blasen verbinden sich → Teil abwerfen (gemeinsam gemocht ODER nicht gemocht) → reine Splitterblase
- System-Analyse-Daemon: Status läuft / loopt / ohnmächtig → Admin-Report
- Herkunftslinien + Ahnenverzeichnis immer gespeichert

**Content-Filter:**
- Schicht 1 (regelbasiert): keine menschliche Beschreibung in wesen_typ
- Schicht 2 (LLM-Check via Ollama): BLOCK bei echtem Übergriff/Kindesmissbrauch, WARN bei Grauzone
- Erlaubt: Obszönität, Beleidigungen, harte Sprache, Wesen schiesst zurück (Grok-Stil mit Witz)

**DB-Schema (geplant, noch nicht gebaut):**
- zwischenwesen, zwischenwesen_nachrichten (inkl. rolle: mensch/wesen/monolog), zwischenwesen_container, zwischenwesen_memory, zwischenwesen_memory_kategorien
- Alle in shared flextrawurst DB
- Keine eigene PostgreSQL pro Wesen oder Splitter

**Schlachtplan-Phasen:**
- Phase 0: ✅ Planung abgeschlossen
- Phase 0.5: ✅ Architektur-Entscheidungen
- Phase 1: DB + API Fundament
- Phase 2: LLM-Integration (Ollama)
- Phase 3: Frontend (FLÜCHTLINGE Tab + FLÜCHTLINGSARCHIV Tab + Content-Filter)
- Phase 4: Prägung + Lande-Zeremonie
- Phase 5: KompOase-Integration
- Phase 6: Splitterblase-Physik
- Phase 7: LangGraph + Inner Monologue + Embeddings (nomic-embed-text)
